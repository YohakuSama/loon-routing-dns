# Security Policy

## Supported version

Only the current configuration in `main` is maintained. Historical tags and
releases (if any) are immutable and are not retroactively patched.

## Reporting a vulnerability

Please use **Security → Advisories → Report a vulnerability** (GitHub private
vulnerability reporting) when enabled. Do **not** open a public issue containing
secrets, tokens, exploitable details or private traffic captures.

If private reporting is unavailable, open a non-sensitive issue asking for a
private contact channel, without disclosing the vulnerability. Maintainers
will triage the report and coordinate a fix and disclosure if necessary.

## Scope

Issues in the configuration, scripts, rule provenance or immutable asset
references are welcome. Network diagnostic responses are not proof of a
service's account-level availability. Do not submit credentials or raw
identifying network logs.
