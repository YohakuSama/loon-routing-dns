# 网络辅助插件

LoonKit 正式配置已内置 **网络辅助插件**，无需重复添加。最新正式配置中的插件独立固定版本，更新 `LoonKit.lcf` 后应在 Loon 内**刷新插件及其脚本资源**。

[查看当前插件](../release/Network_Diagnostics.plugin) · [返回首页](../README.md)

## 七个服务的手动诊断

当前正式配置只有一个「网络辅助」插件。选择 Spotify、Twitch、Abema、BBC、Line、Reddit 或 LinkedIn，再手动运行「服务检测」，可查看主站、关联 HTTPS 端点及 Loon 原生 DNS 查询结果。HTTP 404 表示检测地址没有对应资源，但说明服务器有响应；不据此判断 App 不能使用。查询得到 A 记录而没有 AAAA 记录，不等于 IPv6 网络故障。不会自动扫描、切换节点或上传日志。需要离线查看规则与私密日志汇总，请参阅 [服务与分流排查](./ROUTE_DIAGNOSTICS.md)。

从 v6.1.0 升级的用户，如果曾经额外手动安装过独立「服务连通性诊断」插件，请在 Loon 内删除旧的独立安装项，避免界面上出现重复插件。

## 节点信息

查看所选节点或策略的公网 IP、地区、ASN、ISP 等。默认查询 `Proxy`；可选的「直连 IP 对照」默认关闭，开启后会额外请求直连公网 IP。

## 网络检测

手动运行时使用两个 `generate_204` 端点检查 **直连** 与 **`Proxy` 策略**，并通过 Loon 原生 `$dns.query` 查询 DNS（需要 Loon Build **988+**）。只检测这三项，不更改策略、节点或 DNS 设置。

**版本兼容性：** 插件声明的最低 Loon 版本为 `3.5.1(983)`，但 **DNS 查询功能单独要求 Build 988+**。使用较旧但满足插件最低版本的 Loon 时，节点出口工具仍可使用，DNS 诊断会明确显示“不支持 DNS 查询 API”，而非误报 DNS 故障。

| 显示结果 | 实际含义 |
| --- | --- |
| **网络连接与 DNS 解析正常** | 直连和代理端点均返回预期 `HTTP 204`，且 DNS 查询得到有效 A/AAAA 地址。 |
| **部分检测尚未确认** | 某端点返回 `HTTP 200`、重定向、非预期状态码，或运行环境不支持 DNS API；不能据此说网络已断开。 |
| **检测到连接或解析失败** | 有明确 HTTP 请求错误、超时、DNS 查询失败或无有效 DNS 答案。 |
| **解析成功 · DoH** | Loon 明确报告 `doh`，或 `auto` 返回完整 HTTPS 解析器地址；支持用户自行选择 DNS，不与 AliDNS 强制比较。 |
| **解析成功（缓存）** | DNS 命中缓存；本次查询没有新的传输，不能用于证明传输方式。 |
| **解析成功 · 普通 DNS** | Loon 报告 UDP / 系统解析方式；用户自选普通 DNS 不视为网络故障。 |
| **解析成功（附提示）** | Loon 返回 `auto / https://` 等**不完整**信息时，无法判断本次传输协议；不以 DNS 服务商不同判定异常。 |

### 自定义 DNS 与检测边界

支持按 Loon 返回的数据识别 DoH、DoT 与普通 DNS，不限制解析服务商。**解析成功和传输协议是两个不同的检测结果**；信息不足时会说明无法确定协议。


**注意：** 配置了 `doh-server` 不代表所有应用流量都使用该 DoH；Loon 可能并行查询普通 DNS，且加密 DNS 失败时默认可以回退普通 DNS。插件通过 Loon API 进行的单次查询，也不能证明整台设备、所有 App 或完整传输路径没有 DNS 泄漏。需要严格验证时请结合 Loon DNS 日志及 [DNS 说明](./DNS_PRIVACY.md)。

## 网络切换提醒

**默认关闭**。开启后网络变化时只检查直连连通性；首次明确失败会延迟再次检查，两次明确失败才发送中文通知，同类通知有 30 分钟冷却。HTTP 200、301 等非预期响应不会自动被当作断网，也不会触发失败提醒。

此功能不自动切换节点、不修改 DNS / TUN / 分流规则。
