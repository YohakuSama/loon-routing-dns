# Loon Network Diagnostics & Node Intelligence v1.2

Loon Routing DNS 的**可选插件**，一份插件同时提供：

1. **手动网络诊断**：DIRECT、DoH 与 Proxy 策略连通性。
2. **网络切换故障检测**：Wi-Fi / 蜂窝变化后轻量复测，DoH 故障时去重通知；不自动改变 Loon 的代理运行模式，也不切换 VPN 开关。
3. **节点详情查询**：手动查看指定节点或策略组出口 IP、国家/城市、ASN、ISP 和机房/移动等特征，交叉参考 Loon 本地 GeoIP/ASN；如需要，可主动开启与直连出口对照。

插件**不会修改主配置**、DNS、节点选择、代理策略或 MITM 设置；网络变化时**不会自动查询 IP 情报**。

## 安装

需 **Loon 3.5.1 (Build 983) 或更新版本**。

Loon → 配置 → 插件 → ＋ → 从 URL 导入，粘贴：

```text
https://raw.githubusercontent.com/YohakuSama/loon-routing-dns/main/plugins/Network_Diagnostics.plugin
```

导入、启用插件后，在「通用脚本」中可以选择 **手动网络诊断**、**节点详情查询**。

若安装的是之前的网络诊断插件，**更新同一个插件链接**即可；不要重复安装第二份。项目主配置 v4.4.5 不需要改动。

## 节点详情查询：怎么使用？

**方法 A：查询目前 Proxy 策略使用的节点**

在 Loon 的「通用脚本」页面运行 **节点详情查询**。默认使用插件参数 `target_policy = Proxy`，脚本会通过当前 `Proxy` 策略发出查询，因此报告的是**实际代理出口**，而不是机场订阅里写的服务器入口地址。

**方法 B：查询特定节点或策略组**

如果 Loon 当前版本支持在具体节点/策略组页面运行「通用脚本」，选中目标节点并运行 **节点详情查询**，脚本优先采用 Loon 传入的节点/策略上下文。

也可以在插件参数的 **「默认查询策略组」** 输入实际的节点名称或策略组名称，再从通用脚本页面运行。名称需要与 Loon 内部一致。

**方法 C：只查询直连网络**

把插件的「默认查询策略组」改为 `DIRECT`，再运行「节点详情查询」。

### 报告包含哪些信息？

| 信息 | 示例/解释 |
|---|---|
| 出口 IP | 当前指定节点/策略**真正请求到 IP 查询站点时**使用的公网 IP |
| 国家、州/省、城市、时区、坐标 | IP 情报数据库的**近似位置**，不是精确机房地址 |
| ASN、ISP、运营组织 | 网络注册与自治系统归属线索；不一定等于售卖节点的商家 |
| 机房、家宽、移动网络 | 机房/移动由情报旗标推断；**未标记机房并不等于证实为家宽** |
| VPN、代理、Tor | 情报站的特征标签，可能误报或漏报 |
| 风险分数 | 情报商自身的风控参考，**不是代理质量或安全性评分** |
| 直连出口对照 | 使用 `DIRECT` 单独查询当前网络出口，帮助发现代理策略意外选到直连 |

报告同时展示 Loon 本地 GeoIP / ASN / ASO 核对信息，数据源不一致时仅作参考。明确的节点入口结果可在本机缓存 2 分钟；默认 Proxy / Auto 等动态选择策略不会使用缓存，避免节点切换后返回旧 IP。

报告中「机房/托管组织」只是 ASN 组织线索。**无法从公开 IP 情报可靠获得实际服务器楼宇、机架位置、具体数据中心名称或真实家庭住址。**

### 出现同一个出口 IP 怎么办？

如果「代理出口 IP」与「DIRECT 出口 IP」相同，可能是 `Proxy` 当前选择了 `DIRECT`，也可能是不同路径共用同一公网出口。请检查选中策略、实际节点及 Loon 请求记录。IP 相同提示需要排查，**单次结果不能作为泄漏的充分证据**。

若节点查询失败，脚本只报告失败，**不会自动把 DIRECT 的 IP 当成这个节点的 IP**。

## 网络诊断与网络变化故障检测

| 模式 | 运行时机 | 检测 |
|---|---|---|
| **手动网络诊断** | 用户主动执行 | DIRECT 的 HTTP 204、AliDNS DoH 的 RFC 8484 DNS 查询、Proxy 策略的 HTTP 204；Build 988+ 另测原生 DNS |
| **网络切换诊断** | Wi-Fi / 蜂窝网络变化后 | DIRECT、DoH；失败后延迟复测，确认 DoH 异常时通知 |
| **节点详情查询** | 用户主动执行 | 指定节点/策略出口 IP 情报；可选 DIRECT 出口对比 |

自动检测仅探测连通性，不查询位置或 ASN；正常不通知；同类故障**30 分钟内不会重复提醒**。网络切换时，探测站点可能短暂不可达，因此会在异常后复测一次。

## 插件参数

| 参数 | 默认值 | 用途 |
|---|---|---|
| **待测 DoH 地址**（`doh_url`） | `https://dns.alidns.com/dns-query` | 网络诊断使用的完整 HTTPS DoH URL |
| **网络切换后自动诊断**（`auto_check`） | 开启 | 关闭后仅手动检测 |
| **默认查询策略组**（`target_policy`） | `Proxy` | 节点信息查询目标；在节点/策略入口触发时优先使用入口上下文 |
| **同时查询本地 DIRECT 出口**（`compare_direct`） | 开启 | 查询第二条网络路线以比较出口 IP；关闭可减少一次外部请求 |

修改主配置中的 DoH 后，记得同时更新插件的 DoH 参数；插件不会自动读取主配置中的 DNS 地址。Loon 运行模式仍用 **RULE**，AliDNS DoH 模式用 **DIRECT**，关闭加密 DNS 查询回退。

## 结果不正常如何排查？

| 情况 | 处理方式 |
|---|---|
| 节点 IP 查询失败 | 手动测试 `Proxy` 是否能连通；查看脚本日志中的 API HTTP 状态、代理策略与节点名称 |
| 看到本地直连 IP | 核对 `Proxy` 是否选中 DIRECT；对比手动网络诊断与 Loon 日志 |
| 某节点没有「机房/住宅」信息 | 可能使用备用 ipwho.is，备用源只有位置、ASN、ISP，**不会强行判断家宽** |
| 情报 API 返回 429 | 服务商可能限流；稍后手动重试 |
| 地区显示与机场命名不同 | 地理数据库与节点标签可能不同；实际出口 IP 才是当前查询观察到的地址 |
| DIRECT 正常、DoH 失败 | 检查 DoH URL、TLS 与网络是否能直连服务商；关闭查询回退后解析可能失败 |
| DoH 正常、Proxy 连通性失败 | 排查节点订阅、所选策略组及代理线路 |
| 仅直连 204 探测失败 | 探测 URL 不可达不代表整个网络断网，可结合 DoH 判断 |
| IP 地址信息和服务器提供商不一致 | ASN/ISP 可能显示上游机房或网络承载商，并不必然等于商家名称 |

## 数据来源和隐私

- **主要来源：** [ipquery.io](https://ipquery.io/)，自动从请求所在出口识别公网 IP，并返回位置、ISP、ASN、风险特征；无需用户提供 API Key。
- **备用来源：** [ipwho.is](https://ipwho.is/)，主要提供公网 IP、位置、ASN 和 ISP，不具备同样的机房识别字段。
- **查询路线：** `node: "Proxy"` 或你指定的节点/策略会让 API 收到**该节点的出口 IP**；DIRECT 对照**默认关闭**。只有你手动开启后，服务商才会额外看到**你的直连公网 IP**。这两种查询是手动触发的。
- **本地隐私：** 脚本不读取或发送机场订阅 URL、节点密码、证书或密钥。若不想把直连公网 IP 交给情报服务商，可关闭 `compare_direct`。
- **局限：** IP 情报标签并非权威的住宅/机房证明。任何来源的城市、风险分数、VPN 标志都可能不准确。此插件也不能单凭检测结果证明没有 DNS/WebRTC 泄漏。
