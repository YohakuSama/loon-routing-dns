## 覆盖状态

- 目录共 **87 条来源记录**，其中 **77 条远程链接、10 个本地文件**。

## 自动化验证与未解决事项

每周的 `.github/workflows/rules-update.yml` 会使用 `scripts/upstream_review.py` 抓取全量来源、生成快照、差异与风险材料。为避免「部分来源失败也显示全量成功」，新增 `scripts/verify_upstream_coverage.py`，在审核附件上传后逐个检查：

1. 目录中的来源 ID 与报告中的 ID 完全一致、没有遗漏/重复或额外来源；
2. 每条来源状态为 `PARSED_FOR_REVIEW`，未解析指令数为 0，并达到来源定义的最低数量；
3. 全部原始快照、哈希及来源计数齐全，分组没有被标记为不完整；
4. 审阅报告明确禁止自动发布。

**任何一项失败，审核工作流必须显示来源覆盖不完整，同时保留已有证据附件（如果成功生成）。** 禁止因此绕过审查、直接纳入上游新规则。

后续要解决的不是「无条件接受所有上游语法」，而是通过真正的 GitHub Actions Runner 补齐那个大型来源的读取，并对 URL-REGEX、regexp、include 等逐项判断是否支持、跳过还是以明确可验证的精确规则替代。LoonKit 规则发布仍需独立的策略冲突与真机回归。
