# 上游规则安全审阅

LoonKit 采用**固定发布基线、上游差异审阅与回归测试**维护分流规则，重点检查误拦截、异常直连、共享基础设施误匹配及广告拦截影响。

## 规则变更检查项

| 检查 | 处理方式 |
| --- | --- |
| 新规则、上游规则删除 | 均不得直接进入正式规则；保留已发布基线。 |
| 上游不可用、格式不支持、规则数量不合要求 | 记为来源不完整；本次候选不能当作可直接发布的完整更新。 |
| 公共后缀、整个多租户托管域名 | 语法合法时**保留原始证据并提高审查优先级**，如 `co.uk`、`github.io`、`cloudfront.net`；不自动发布。完整公共后缀识别不能只依赖静态示例表。 |
| 过短关键词、无效域名与过宽 IP 网段 | **畸形规则拒绝解析**；语法合法但范围宽的短关键词、网段等保留并标记风险，不一刀切丢弃。 |
| 新增 `DOMAIN-SUFFIX` | 统一标记 `NEW_SUFFIX_SCOPE_REVIEW`；普通服务后缀按常规审核，有公共后缀、多租户或跨策略覆盖风险时提高优先级。 |
| 相同匹配但目标策略不同 | 标记精确冲突；不会按抓取或下载顺序自行决定归属。 |
| 域名及 IPv4/IPv6 网段交叠 | 同时比较现役规则及本次其他候选，列出冲突策略。 |
| 新的广告拦截域名 | 全部要求来源与用途审核；支付、登录、共享基础设施另加误杀风险标签。 |
| 大幅增删规则 | 记录数量变化及全量差异，超过 20% 的分组变化额外提示人工核对。 |
| 精确去重、同策略 `DOMAIN` 被 `DOMAIN-SUFFIX` 覆盖 | 仅用于审核候选的规范化展示；不会改变已发布规则。 |

## 实际格式语义与压力测试

`DOMAIN-SET` 的**无前导点域名**转换为 `DOMAIN`（仅匹配本域名）；**带前导点域名**转换为 `DOMAIN-SUFFIX`（包含子域）。不能为简化去重把两者都改成后缀匹配，否则会扩大广告误拦截范围。候选来源报告的 `rule_kinds` 会分别统计转换后的匹配类型。

上游 v2fly 支持独立域名、`full:` 精确域名、`domain:` 后缀及行尾注释；`include:` 引用通过受限递归展开与快照校验处理。`regexp:` 无法安全等价转换为普通域名规则时，将原文及原因记录到审核报告。

独立审计中使用固定随机种子的朴素算法交叉校验快速的域名/IP 覆盖索引，对照同策略去重前后的匹配结果，并对正式广告、直连、支付登录域名做保护检查。随机压力测试仅验证已覆盖的逻辑性质，不能替代实际客户端网络访问和所有来源的授权确认。

## 自动化实际会做什么

`.github/workflows/rules-update.yml` 每周运行 `scripts/upstream_review.py`，只读获取登记的上游来源，并生成以下材料：

- `UPSTREAM_REVIEW.json`：来源可用性、格式错误、分组统计、审核状态和安全边界。
- `FULL_DIFF.json`：每个策略组的**完整新增、删除匹配**，不是只保留前几十个示例。
- `FULL_RISK_AUDIT.json`：每条新增规则的风险原因、具体来源 ID、涉及的其他策略组，以及各条删除的审核要求。
- `CANDIDATE_SOURCES.json`、`snapshots/`：可复核的原始来源与其 SHA256。
- `candidate/*.list`：**只含当前已发布基线**，用于比对，绝不混入本周任何未审核的新增或删除。

候选审阅分三级：① 无效表达式保留错误记录，不作为规则候选；② 有范围或策略风险的合法规则标记为 `ELEVATED`；③ 常规合法规则标记为 `STANDARD`。所有候选仍须审阅后才能进入新版本，已锁定规则保持不变。

上游审核结果由 `scripts/verify_upstream_coverage.py` 分开判定：**87 条来源完整读取和逐行分类**，以及**是否所有表达式都可以安全转成规则**。未知语法、缺失来源/快照/哈希、无效排除证据仍使工作流失败；已识别但不可等价转换的 URL 或主机名正则只作带 SHA256 的明确排除项，不会进入候选规则。本轮真实运行读取 87/87 来源，展开 10 个 V2Fly 引用，隔离 8 条正则；详见[上游审计](./UPSTREAM_COVERAGE_2026-10-21.md)。

上游审阅产物设置 `publication_allowed = false`，发布需由维护者在独立 PR 中核准，并完成输入重新锁定、版本构建及分流回归。

## 分流策略的人工复核

域名归属可能因 CDN、共享托管、广告/统计服务及跨境部署发生变化。`DOMAIN-KEYWORD`、宽 `DOMAIN-SUFFIX`、IP 网段与 ASN 更可能同时命中无关业务；盲目改窄又可能漏掉实际 App 所需的 API/CDN 域名。上游规则仅提供**候选证据**，不等于已经验证适用于 LoonKit 的策略顺序。

广告规则重点检查支付、登录、验证码、系统更新及多租户 CDN。范围较广的候选规则进入优先审核队列；现役广告拦截仍由用户在 `AdBlock` 策略组中选择 `REJECT` 或 `DIRECT`。

## 维护者发布前检查

先查看全部差异与全量风险表，对每个策略组确认**新增和删除的实际行为**；再验证重要国内站点直连、海外服务、广告拦截、支付与登录、DNS 诊断、IPv4/IPv6、未知域名的 `Final`。现有静态和离线测试可防止已知回归，但不能替代真机请求、真实广告效果与新增域名的实际归属验证。
